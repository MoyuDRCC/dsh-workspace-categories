# 工作区分类

为 DSH（DeepSeek Harness）侧栏的工作区列表增加一层**自定义分类**：把十几个平铺的工作区收进
「项目 A / DSH 插件 / 客户项目」这样的桶里，需要时再展开。

分类是纯视图层数据，不改写任何内置记录——工作区、会话、归档与置顶状态全部保持官方行为。

- 版本：0.2.0 · 许可：MIT · 适配 DSH：`0.2.2-rc.1`
- 界面语言：简体中文 / English / 日本語 / Español / Français / Deutsch / Русский / Português

---

## 功能

| 能力 | 说明 |
| --- | --- |
| 新增分组方式 | 视图菜单里多出「按分类」，与内置的按工作区 / 按工作区树 / 单列表并存，随时可切回 |
| 两种呈现 | **树形**（分类头就地展开成员）与**进入式**（像文件管理器，两级浏览），偏好记在本地 |
| 分类管理 | 新建、重命名、删除；删除分类不会删除工作区，成员回到「未分类」 |
| 归类 | 把工作区行拖到分类头上，或用工作区 `⋯` 菜单的「移动到分类…」/「移出分类」 |
| 排序 | 拖动分类行到另一个分类的前/后半区（树形与进入式根级都可用）；分类顺序即展示顺序 |
| 视觉标记 | 每个分类有固定彩色圆点（12 色板按分类 id 稳定散列，同屏互不重复，超出后开始复用），成员缩进与分类头箭头对齐 |
| 定位当前会话 | 标题栏准星按钮：展开所属分类并滚动到当前会话行，需要的层级自动展开 |
| 跟随当前会话 | 进入式下切换会话会切到该会话所属分类，避免「正在开会话、左栏却在看别处」 |
| 跨窗口一致 | 分类与归属由 Host 侧持有，多窗口共用同一份数据（写入带版本校验） |
| 其余一切照旧 | 搜索、置顶、归档三态、手动排序、拖拽、悬浮卡、快捷键、启动恢复、新会话页选题器、`ssh://` 工作区 |

## 安装

要求 DSH `0.2.2-rc.1`（`package.json` 的 `engines.dsh`）。

**推荐**：在 DSH 的插件管理里安装本目录，插件管理器会把本包登记进 profile 的依赖与 bundle 清单。

**手动**（profile 目录，例如 `$DSH_HOME/profiles/web`）：

```jsonc
// package.json
{
  "dependencies": {
    "dsh-workspace-categories": "link:/absolute/path/to/工作区分类"
  },
  "dsh": {
    "profile": {
      "bundles": [
        // …其它 bundle
        "dsh-workspace-categories"
      ]
    }
  }
}
```

在该 profile 目录执行 `pnpm install`，重启 DSH 并刷新页面。客户端模块不会热替换。

**卸载**：从 `bundles` 里移除本包（等同停用），再移除依赖并删除包目录。分类数据保留在
`plugin-data` 下，重新启用后继续可用。

## 使用

### 切换到分类视图

列表标题栏的 `⋯`（视图选项）→ **分组方式** → **按分类**。原有的三种分组方式保持原样。

同一菜单里的 **分类展示** 决定分类怎么摆：

- **树形（就地展开）**：一屏看到全部层级，适合跨分类浏览，工作区行可直接拖到任意分类头。
- **进入式（像文件管理器）**：根级只列分类，点进去看该分类的工作区，顶部「‹ 返回」回根级；
  同屏只有一个分类，跨分类归类改用工作区 `⋯` 的「移动到分类…」。

两种呈现的状态互不覆盖：树形的折叠、进入式上次所在的分类，都各自记住。

### 新建与整理

| 操作 | 入口 |
| --- | --- |
| 新建分类 | 头部 `+` 菜单 →「新建分类」；进入式根级最下一行也有「＋ 新建分类」 |
| 重命名 / 删除 | 分类头右侧 `⋯` →「重命名分类」/「删除分类」 |
| 归类 | 工作区行 `⋯` →「移动到分类」→ 选分类；或直接拖到分类头 |
| 移出分类 | 工作区行 `⋯` →「移出分类」 |
| 调整分类顺序 | 拖动分类行到目标分类的前/后半区（进入式在根级拖动） |

- 分类只有一级，不做子分类；不按路径或主机自动归类，一律手工。
- 未归类的工作区（含不属于任何工作区的游离会话）归入末尾的「未分类」桶，空则不显示。
- 分类内的工作区顺序仍是内置顺序，拖拽工作区即调用内置的 `insertBefore`，没有第二套排序。

### 定位当前会话

标题栏的准星按钮（悬停提示「定位当前会话」）：

- 树形：展开所属分类与工作区，滚动到会话行并高亮。
- 进入式：切到该会话所属分类，再滚动到行。
- 当前会话被筛选隐藏时（归档筛选为「隐藏已归档」或「仅显示已归档」），自动切换到可见状态，
  不改变任何归档数据。搜索框会被清空。
- 没有当前会话、侧栏面板已打开、工作区数据未就绪，或当前是子智能体的会话时，按钮不可用；窄栏下不显示。

## 数据与接口

### 分类数据（Host 持有）

```text
${DSH_HOME}/plugin-data/dsh-workspace-categories/state.json
```

```json
{
  "rev": 12,
  "categories": [
    { "id": "cat_example1", "name": "项目 A" },
    { "id": "cat_example2", "name": "DSH 插件" }
  ],
  "assignments": {
    "0f8c2b7d-…-workspace-id": "cat_example1"
  }
}
```

- `categories` 的数组顺序即展示顺序，没有额外的 `order` 字段。
- `assignments` 里没有的 workspaceId = 未分类；它不入盘成一个显式桶。
- 写入走「临时文件 + rename」原子替换，避免半个文档落盘。

### 端点

```text
GET  /api/dsh-workspace-categories/state
     → { rev, categories, assignments }
PUT  /api/dsh-workspace-categories/state   { rev, categories, assignments }
     → { rev }            rev 不匹配时 409：另一个窗口先写过，客户端重取并提示重试
```

- 仅接受回环地址（`127.0.0.1` / `::1`）；其它来源 403。
- `PUT` 要求 `application/json`，请求体上限 256 KB。
- 每次读取都用 `workspaceRegistry` 现存的工作区 id 对账：工作区被删除（含 ssh 工作区卸载）后，
  遗留的归属会在读取时自动裁掉并写回。

### 视图状态（浏览器本地）

`dsh-workspace-categories.ui`：分类呈现方式、进入式所在分类、树形各分类的折叠状态。
折叠与所在位置属于单窗口视图偏好，不进 Host，因此不会为了折叠一次而写盘。

## 设计说明：为什么要接管内置工作区浏览器

侧栏浏览区是单占用槽位 `sidebar.workspaces`，它声明的 5 个子洞只有声明者能渲染、同一 key 不许二次声明。
而内置的 `@deepseek-ai/dsh-client-ui-workspace` 同时提供共享服务 `ctx.uiWorkspace`——侧栏外壳、会话页、
新会话页、日程、目录选择器都在注入它，并且启动恢复上次会话、空安装时创建默认工作区也在这里。

所以本插件不是「在旁边叠加一个视图」，而是把它整份取进 `client.js`（MIT，见
[THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)），保留全部服务、槽位与子洞，**只在列表渲染处加入分类层**。
改动用 `// [categories]` 标记，共 12 处：

1. 工作区载荷登记：分类头只认工作区，不把会话行当成可归类对象
2. 分组方式新增 `category`；分类层只在选中它时接管列表
3. 分类呈现方式（与分组方式正交）
4. 分类数据与视图状态；进入式跟随当前会话，分类被删后回到根级
5. 由渲染层决定分类模式的空态与行键；数据未就绪或失败时退回内置渲染
6. 分类拖动排序：源分类插到目标分类的前/后半区
7. 按分类分桶：分类桶包住原有的工作区分组，进入式在根级与分类内两级切换
8. 头部 `+` 菜单的开合状态（宽栏与窄栏共用一套）
9. 头部 `+` 的菜单项：添加工作区与新建分类并列，不再直接跳目录选择
10. 先行取分类数据，渲染时只读快照，不在组件里发请求
11. 工作区 `⋯` 菜单的「移动到分类」子菜单（没有分类时给新建入口）
12. 分类的新建 / 重命名 / 删除对话框，挂在浮层而非列表里

### 文件构成

| 文件 | 内容 |
| --- | --- |
| `index.js` | Host 半边：分类持久化、对账、HTTP 路由 |
| `client.js` | 客户端半边：内置浏览器副本 + 分类层（单文件模块，无构建步骤） |
| `cordis.patch.yml` | 本插件自带的 patch 层：禁用内置行、插入本插件行 |
| `locale/*.json` | 插件的标题与描述（8 种语言文案在 `client.js` 内） |
| `docs/design.md` | 完整设计方案：实测事实、路线对比、改动清单、风险 |

`client.js` 即发布产物，直接由 DSH 的客户端模块加载器读取，仓库里没有构建脚本。

## 恢复官方默认

1. 在插件页把 `dsh-workspace-categories` 这个 **bundle** 关掉（不是只关插件行）；
2. 组合重算，内置 `ui-workspace` 行恢复启用；
3. 刷新页面。

结果：侧栏回到官方默认，会话选择、工作区数据、归档/置顶状态全部原样——分类数据只活在
`plugin-data` 下。重新打开 bundle 即回到分类视图，分类还在。

三个必须遵守的前提：

1. `disabled: true` 只能写在本插件自带的 patch 里。写进 profile 的 `cordis.patch.yml` 会永久生效，
   插件关掉后官方浏览器也回不来。
2. 回退要停 bundle，不要只把插件行标成 `disabled`：patch 层仍在时，官方浏览器继续被禁、本插件视图也没了，
   而 `ui-sidebar` 拿不到 `ctx.uiWorkspace` 连外壳都不挂载——界面会直接失去左栏。
3. 客户端要刷新页面：宿主组合立即重算，但已打开页面里加载的客户端模块不会自己换。

## 开发

- **无构建、无测试框架**：`index.js` / `client.js` 就是运行时代码，改完刷新页面即可看到结果。
- **升级 DSH 后同步 vendor**：重新取内置 `@deepseek-ai/dsh-client-ui-workspace`（目标版本），
  按 `// [categories]` 标记重放分类层，并核对 5 个外部依赖
  （`react`、`react/jsx-runtime`、`@deepseek-ai/cordis`、`@deepseek-ai/dsh-client-store`、
  `@deepseek-ai/dsh-client-ui-primitives`）是否仍可解析。
- **改动前先核对契约**：用 `cordis_inspect_query` 查客户端 `Slots` / `Service`，确认
  `sidebar.workspaces`、`ctx.uiWorkspace` 与 5 个子洞没有变化。
